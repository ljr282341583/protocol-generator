# 人民调解协议生成器

> 纯前端HTML单页面应用，即开即用，自动生成规范的人民调解协议书及全套配套卷宗文书。

## 快速开始

1. 选择对应方案的 HTML 文件
2. 用浏览器打开即可使用
3. 无需安装任何依赖，无需服务器

## 核心功能

### 协议生成
- 多种预设纠纷类型（邻里纠纷、婚姻家庭、损害赔偿、合同纠纷、劳资纠纷、房屋宅基地、治安纠纷等）
- 当事人信息录入（支持个人/单位切换）
- 自动/手动生成协议书编号
- 可自定义调解协议条款
- 事实与理由支持模板导入导出、合并填写

### 文书导出
- **全套卷宗文书**（12种）：申请书、受理登记表、调查记录、调解记录、协议书、送达回执、权利义务告知书、口头协议登记表、回访记录、司法确认申请书、卷宗封面、情况说明
- **个人卷宗文书**（8种）：卷宗标准封面、新卷内目录、回访记录、登记单、情况说明、收据、谅解书、未成年情况说明
- **治安文书**：治安调解申请书、治安调解协议书（原版 docx 格式导出）
- 支持 Word 导出（.doc 格式，宋体/仿宋字体，A4 页面设置）
- Word 原生分页符，每个文书独立分页
- HTML 预览、复制文本、直接打印

### 模板管理
- 纠纷类型模板 JSON 导入/导出
- 支持自定义纠纷类型和条款模板

### 证件号码校验（v5.7 新增）
- **18位身份证**：格式、省份代码、出生日期（含闰年）、MOD 11-2 校验位四层校验，小写 x 自动转大写
- **统一社会信用代码**：18 位结构 + MOD 31-1 校验位校验（单位当事人）
- 即时提示：输错红框 + 具体原因，通过显示绿勾；15 位老证警告但允许
- 自动带出：校验通过后自动回填出生日期、年龄、性别（第 17 位奇偶判断）
- 软校验闸口：下一步及各导出前如存在未通过号码，弹确认框可选择性继续

## 授权方案对比

| 特性 | 方案一（启动密码） | 方案二（授权码 + 设备绑定） |
|------|-------------------|---------------------------|
| 授权方式 | 启动密码 | 授权码 + 设备指纹 |
| 设备绑定 | 无 | Canvas/WebGL 指纹，SHA-256 哈希 |
| 云端存储 | 无 | Supabase |
| 多设备 | 不限制 | 一码一设备（可配置上限） |
| 远程管理 | 无 | 管理员面板远程撤销/重新激活 |
| 定时校验 | 无 | 30秒定时检查授权状态 |
| 离线回退 | N/A | Supabase 不可用时回退 localStorage |
| 适用场景 | 内部使用 | 对外分发，需管控授权 |

## 更新日志

### v5.7 — 2026-08-29

#### 新增：证件号码校验
- **18位身份证四层校验**：格式（18位、末位数字或X）→ 省份代码（前两位行政区划）→ 出生日期段（真实日期含闰年、不晚于今天）→ MOD 11-2 校验位；输入时自动去空格、小写 x 转大写 X
- **统一社会信用代码校验**：单位当事人的 18 位代码按 GB 32100-2015（MOD 31-1）校验，非法字符（I/O/S/V/Z）与校验位错误均提示
- **即时校验提示**：输满 18 位或失焦即校验——未通过红框 + 红字给出具体原因（位数/省份/日期/校验位分别提示），通过显示绿勾；15 位老式身份证警告但允许通过
- **自动带出信息**：身份证校验通过后自动回填出生日期、年龄，性别为空时按第 17 位奇偶自动填入（已手动填写的性别不覆盖）
- **覆盖范围**：第 2 步当事人（个人身份证 + 单位信用代码）、治安纠纷甲乙方身份证、个人卷宗模块 5 个身份证字段（收据收款人、谅解书甲乙方、登记单甲乙方）
- **软校验闸口**：第 2 步进入下一步及 4 个导出入口（全套卷宗、个人卷宗、调解记录表 docx、治安文书 docx）前，如存在未通过校验的号码，弹出确认框列出具体问题，可选择继续——不硬阻断现场使用

### v5.5.1 — 2026-08-29

#### 修复：老内核浏览器导出 docx 失败
- 修复「导出失败：Failed to construct 'DecompressionStream': Unsupported compression format: 'deflate-raw'」
- 原因：Chromium 80~102 内核（部分国产双核浏览器、微信内置浏览器、旧版 Edge 等）有 DecompressionStream API，但不支持 `deflate-raw` 压缩格式（Chromium 103+ 才支持），导致卷宗标准封面、调解记录表、治安调解申请书/协议书等所有「原 docx 格式」导出失败
- 修复方案：启动时自动检测 `deflate-raw` 支持情况——新内核（Chrome/Edge ≥ 103）仍走原生 API 行为不变；不支持的浏览器自动回退到页面内嵌的纯 JS deflate 解压/压缩实现（puff 算法），无需更换浏览器即可正常导出
- 兼容性说明：兜底路径经过 Node zlib 交叉验证与 .NET zip 独立解包验证，导出的 docx 完全合法；文件已更名为 `人民调解协议生成器启动码v5.5.1.html`

#### 修复：全套卷宗「人民调解记录」显示 undefined
- 原因：v5.5 新增的「调解记录表」独立模块渲染函数与全套卷宗的 `renderMediationRecord(dateStr)` 重名，JS 后声明的同名函数覆盖前者，导致卷宗预览取到 `undefined`
- 影响：全套卷宗「人民调解记录」标签页及「批量导出全部卷宗」导出的 Word 中该页均显示 undefined
- 修复：模块渲染函数更名为 `renderMediationRecordModule()`，全套卷宗版恢复生效；已全量扫描确认无其他顶层同名函数冲突
